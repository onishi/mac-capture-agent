## 4. 判断事項

| ID | 論点 | 選択肢 | 推奨 | 期限 |
| --- | --- | --- | --- | --- |
| D-1 | SQLite の使い方 | (a) GRDB（SPM 依存を追加） (b) システムの SQLite C API を薄く包む | **決定: (a) GRDB 7**（2026-10）。GRDB は Linux 非対応のため、ストアのテストは macOS の CI で実行 | 決定済み |
| D-2 | クラウド AI の提供元 | Anthropic / OpenAI / その他、または複数を切替 | ~~決定: Google Gemini~~（2026-10）→ **D-7 により廃止** | 廃止 |
| D-3 | 著名人の推定を入れるか | (a) 入れない (b) 公人のみ・オプトイン・クラウドのみ | **決定: (b)**（2026-10）。ただし顔画像からの特定はしない。顔が写っているときに、画面上の文字に出ている人名と周辺テキストだけで公人かどうかと人物情報を判定（確度 0.75 以上、画面上の名前と一致する場合のみ表示）。v0.11 から判定は端末内の LLM（D-7） | 決定済み |
| D-4 | ネットワーク Entitlement の追加 | 追加する / オプトイン版を別ビルドにする | ~~決定: 追加する~~（2026-10）→ **D-7 により削除**（v0.11） | 廃止 |
| D-5 | ブラウザの URL を取得するか | Apple Events / 取得しない | **決定: Apple Events で取得する**（2026-10）。Safari と Chromium 系、クエリ等は保存しない、設定でオフ可。macOS がブラウザごとに許可を求める | 決定済み |
| D-6 | 配布方法 | Developer ID（直接配布） / Mac App Store | Developer ID。Apple Events や将来の権限で審査上の制約を受けにくい | v1.0 前 |
| D-7 | クラウド LLM を使うか | (a) オプトインで使う（v0.8〜v0.10） (b) 使わない（ローカルのみ） | **決定: (b)**（2026-10、ユーザー判断）。精度は下がってもよいのでローカルだけで完結させる。Gemini とネットワーク Entitlement を削除し、Foundation Models・Apple のオンデバイス ML・ルールで代替する | 決定済み |
| D-8 | ローカルの追加モデル（Core ML / MLX の VLM・汎用 LLM）を同梱・取得するか | (a) 入れない (b) 小型 VLM を同梱（数百 MB〜） (c) ユーザーが置いたモデルを読む | (a) 当面は入れない。画像を直接見られないのが最大の精度の制約なので、Foundation Models の画像入力が使えるようになればそれを優先。(b)(c) は外部依存とアプリサイズの判断が必要 | M6 後半 |

## 6. 進め方のルール

- 作業ブランチで開発し、CI（Linux のコアテスト＋macOS 15 / 26 のビルドとテスト）が通ってから main にマージする。
- 新しいロジックはまず `AmbientCore` に純粋関数・値型として書き、ユニットテストを付ける。
- クラウド LLM・外部 API・ネットワーク通信は使わない（D-7）。新しい権限・Entitlement・外部依存（ローカルモデルを含む）は §4 に判断事項として記録してから追加する。
- 機能を追加・変更したら SPEC の状態列、MANUAL、README、CHECKLIST（実機で確認すべき点）を更新し、このバックログから消す。
