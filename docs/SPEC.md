# Ambient Screen Intelligence 製品仕様書

> macOS 常時画面解析 AI アプリ — 「Mac の画面そのものに、知性のレイヤーを追加する」

- 文書の位置づけ: 製品要件の正本（Single Source of Truth）。実装方法と設計方針は [ARCHITECTURE.md](ARCHITECTURE.md)、次の作業とアイデアのバックログは [ROADMAP.md](ROADMAP.md)、実機検証は [CHECKLIST.md](CHECKLIST.md)、利用者向けの説明は [MANUAL.md](MANUAL.md)。
- **2026-10 の方針変更（ROADMAP D-7）**: クラウド LLM（Gemini）を廃止し、すべてをローカル（ルール・Apple のオンデバイス ML・Foundation Models）で行う。精度が下がることは許容し、推定であることを表示する。
- 要件 ID は変更しない（廃止時は「廃止」と明記して残す）。
- 状態の凡例: ✅ 実装済み / 🟡 一部実装 / ⬜ 未着手 / ⛔ 方針として実装しない
- **注意**: 2026-10 時点の実装はすべて CI（macOS ビルド＋ユニットテスト）で確認済みだが、**実機での動作検証は未実施**。

## 1. 概要

### 1.1 目的

macOS 上でユーザーが見ている画面を継続的に観察し、AI が内容を理解・分析して、**必要な情報だけ**をリアルタイムに補足表示する。

ユーザーが「これを調べて」と指示するのではなく、AI 側が画面を理解して次のような支援を自動で行う。

| 画面の内容 | 支援 |
| --- | --- |
| 外国語 | 翻訳する |
| 著名人 | 画面に書かれた名前から誰かを推定する（制約あり、§6） |
| 動植物 | 種類を推定する（端末内の推定、精度は低め） |
| 地名・建築物 | 場所や背景を説明する |
| 専門用語 | 意味を補足する（画面で定義された略語は AI なしでも展開） |
| 単位 | マイル・°F・ポンドなどを換算する（ポインタを置いたとき） |
| エラー | 原因候補を示す |
| 過去に見たもの | 再登場を知らせる |

単なる OCR ツールやスクリーンショット解析ではなく、常に存在する「視覚的 AI アシスタント」を目指す。

### 1.2 最終ビジョン

> ユーザーが見ているデジタル世界を、ユーザーと一緒に見ている AI

理解する・関係づける・思い出す・調べる・補足する・警告する。ただし **必要なとき以外は何もしない**。
理想は「あ、それ知りたかった」という情報が、ユーザーが検索する直前に静かに現れること。

## 2. プロダクト原則

| ID | 原則 | 状態 |
| --- | --- | --- |
| P-1 | **何を表示するかより、何を表示しないか**。既定の判断は ignore | ✅ |
| P-2 | イベント駆動: キャプチャ → 差分 → 変化領域のみ解析 → ルール → オンデバイス ML → オンデバイス LLM（必要時のみ） | ✅ |
| P-3 | **Local Only**。クラウド LLM・外部 API は使わない。アプリは通信しない（D-7） | ✅ v0.11 で Gemini とネットワーク Entitlement を削除 |
| P-4 | 通常時はほぼ何も表示しない。数秒で自然に消える。操作を邪魔しない | ✅ |
| P-5 | 一度理解済みのものは繰り返し説明しない | ✅ クールダウン・学習・既知用語（KNOWN / 3 回で停止） |
| P-6 | 詳細は知りたいときだけ展開する | ✅ ホバーで More 操作 |
| P-7 | 失敗時は何も表示しない（技術的エラーをユーザーに見せない） | ✅ 例外: 丸で囲んだ明示的な依頼に答えられないときだけ `NO INTEL` を短く出す（LA-60） |
| P-8 | 精度よりローカル完結を優先し、推定は推定と表示する（画面上の文字で裏付けがあるときだけ断定） | 🟡 「かもしれません」の付与。出典表示は未実装（LA-51） |

## 3. 機能要件

### 3.1 Screen Intelligence（中核）

| ID | 要件 | 状態 | 備考 |
| --- | --- | --- | --- |
| SI-1 | ScreenCaptureKit (`SCStream`) でディスプレイを取得 | ✅ | メイン or ポインタのあるディスプレイ |
| SI-2 | ウィンドウ / アプリ単位のキャプチャ対象指定 | ⬜ | 除外アプリはキャプチャ画像から除去済み |
| SI-3 | 前フレームとの差分検出、変化領域のみ解析 | ✅ | セル単位ピクセル差分、動画等の連続変化は抑制 |
| SI-4 | 領域抽出（字幕・画像・人物・Terminal などの種類別） | 🟡 | 変化領域の矩形のみ。種類別の検出は未実装 |
| SI-5 | 認識対象: テキスト | ✅ | Vision OCR |
| SI-6 | 認識対象: 動物・植物・食品・ランドマーク・人物（粗分類） | 🟡 | `VNClassifyImageRequest` の粗分類と具体的なラベル（例: kingfisher）を、周辺の文字とともに Foundation Models に渡して推定（LA-1）。人物は顔の有無と画面上の文字を使う |
| SI-7 | 認識対象: 商品・ロゴ・グラフ・地図・UI | 🟡 | 商品・食品は SI-6 と同じ経路で推定（ロゴ専用モデルはない）。グラフ・地図・UI は未対応 |
| SI-8 | 認識対象: ソースコード・エラーメッセージ | ✅ | Coding Mode（§3.6） |
| SI-9 | 認識対象: QR コード・URL・日付・金額・単位 | 🟡 | QR コード（Vision）の行き先を HUD に表示。ポインタを置いたとき・丸で囲んだときに、ヤード・ポンド法の数量をメートル法に（LA-15）、他のタイムゾーンの時刻・Unix 時刻・ISO 8601 を手元の時刻に、日付を「13日後（火）」に換算（LA-16〜18）。金額は未対応 |

### 3.4 識別（動植物・ランドマーク・人物）

| ID | 要件 | 状態 | 備考 |
| --- | --- | --- | --- |
| ID-1 | 動植物の種類推定（和名・学名・分類・生息地） | ✅ | 大きな画像変化を Vision で分類 → 具体的なラベル＋周辺の文字を Foundation Models に渡して推定（20 秒に 1 回まで、LA-1）。画像そのものは LLM に渡らないため精度は低い |
| ID-2 | 確信度が低い場合は断定しない（「〜かもしれません」） | ✅ | LLM の自己申告は信用せず、分類ラベルの確度で上限をかける。0.55 未満は表示しない。画面上の文字に名前が出ているときだけ断定、それ以外は「かもしれません」 |
| ID-3 | ランドマーク推定（名称・場所・建築家など） | ✅ | ID-1 と同じ経路 |
| ID-4 | 著名人・公人・ユーザー登録人物の推定 | 🟡 | 公人のみ。顔が写っているときに画面上の人名＋周辺テキストを Foundation Models の知識で判定（LA-2）。顔からは特定しない。ユーザー登録人物は未対応 |
| ID-5 | 一般人の身元をネット情報から自動特定する | ⛔ | 実装しない |

## 6. 人物推定に関する制約（ID-4 / ID-5）

- 対象は **著名人・公人・ユーザーが事前登録した人物** に限る。
- 一般人の身元をインターネット上の情報から特定する機能は **実装しない**。
- 顔画像・顔特徴量は保存しない。登録人物の場合のみ、ユーザーの明示的な同意のうえでローカルに保持する（設計は v0.8 で確定）。
- 確信度が低い場合は表示しない（「〜かもしれません」としても出さない）。
- 判定は端末内の LLM の知識だけで行う（v0.11〜）。画面に書かれた名前と答えの名前が一致しない場合は表示しない。

## 7. 用語
