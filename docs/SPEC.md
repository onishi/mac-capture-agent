# Ambient Screen Intelligence 製品仕様書

> macOS 常時画面解析 AI アプリ — 「Mac の画面そのものに、知性のレイヤーを追加する」

- 文書の位置づけ: 製品要件の正本（Single Source of Truth）。実装方法は [ARCHITECTURE.md](ARCHITECTURE.md)、順序と計画は [ROADMAP.md](ROADMAP.md) を参照。
- 要件 ID は変更しない（廃止時は「廃止」と明記して残す）。
- 状態の凡例: ✅ 実装済み / 🟡 一部実装 / ⬜ 未着手 / ⛔ 方針として実装しない
- **注意**: 2026-10 時点の実装はすべて CI（macOS ビルド＋ユニットテスト）で確認済みだが、**実機での動作検証は未実施**。

## 1. 概要

### 1.1 目的

macOS 上でユーザーが見ている画面を継続的に観察し、AI が内容を理解・分析して、**必要な情報だけ**をリアルタイムに補足表示する。

ユーザーが「これを調べて」と指示するのではなく、AI 側が画面を理解して次のような支援を自動で行う。

| 画面の内容 | 支援 |
| --- | --- |
| 外国語 | 翻訳する |
| 著名人 | 誰かを推定する（制約あり、§7.3） |
| 動植物 | 種類を推定する |
| 地名・建築物 | 場所や背景を説明する |
| 専門用語 | 意味を補足する |
| エラー | 原因候補を示す |
| 過去に見たもの | 再登場を知らせる |

単なる OCR ツールやスクリーンショット解析ではなく、常に存在する「視覚的 AI アシスタント」を目指す。

### 1.2 最終ビジョン

> ユーザーが見ているデジタル世界を、ユーザーと一緒に見ている AI

理解する・関係づける・思い出す・調べる・補足する・警告する。ただし **必要なとき以外は何もしない**。
理想は「あ、それ知りたかった」という情報が、ユーザーが検索する直前に静かに現れること。

## 2. プロダクト原則

| ID | 原則 | 状態 |
| --- | --- | --- |
| P-1 | **何を表示するかより、何を表示しないか**。既定の判断は ignore | ✅ |
| P-2 | イベント駆動: キャプチャ → 差分 → 変化領域のみ解析 → ローカル判定 → 必要時のみ高性能 AI / Web | ✅（ローカル部分） |
| P-3 | Local First。クラウドは必要時のみ、切り抜き領域だけを送る | ✅（クラウド未実装） |
| P-4 | 通常時はほぼ何も表示しない。数秒で自然に消える。操作を邪魔しない | ✅ |
| P-5 | 一度理解済みのものは繰り返し説明しない | ✅ クールダウン・学習・既知用語（KNOWN / 3 回で停止） |
| P-6 | 詳細は知りたいときだけ展開する | ✅ ホバーで More 操作 |
| P-7 | 失敗時は何も表示しない（技術的エラーをユーザーに見せない） | ✅ |

## 6. 人物推定に関する制約（ID-4 / ID-5）

- 対象は **著名人・公人・ユーザーが事前登録した人物** に限る。
- 一般人の身元をインターネット上の情報から特定する機能は **実装しない**。
- 顔画像・顔特徴量は保存しない。登録人物の場合のみ、ユーザーの明示的な同意のうえでローカルに保持する（設計は v0.8 で確定）。
- 確信度が低い場合は表示しない（「〜の可能性」としても出さない）。

## 7. 用語

| 用語 | 意味 |
| --- | --- |
| HUD | 画面最前面に重ねて表示する補足情報カード |
| Intel | HUD に表示した情報 1 件（翻訳・解説など） |
| BRIEF | Intel に付ける一行の補足（オンデバイス LLM 生成） |
| Archive | Visual Memory の検索画面 |
| Interest Region | マウスの滞在などからユーザーの関心が高いと推定した領域 |
| Knowledge Cache | エンティティごとの解説・検索結果のキャッシュ（30 日） |
